# 0010 — 可靠性与性能验收

状态：待验收（2026-10-16，可靠性修复与本机回归已实现；发布硬件/长时矩阵未完成）。依赖：0003–0009。规格依据：[spec.md](spec.md)。进度入口：[progress.md](progress.md)。

## Task 整体描述

在真实 Windows 设备上验证长时录制、复杂编辑、恢复和 GPU 差异，形成可发布能力边界。

## Task 具体实现逻辑

1. 建立 docs/validation/ 中的硬件矩阵，涵盖 Intel/AMD/NVIDIA 可取得机器、混合 GPU、多屏与不同 DPI。无法取得的配置保留待验收。
2. 运行至少 30 分钟 1080p60 动态录制，检查音画偏差、丢帧、内存、纹理池、线程/句柄数量和文件完整性。
3. 在硬件支持时测量 4K60，并分别记录采集、预览和导出性能；不能把编码补帧率当屏幕实际捕获率。
4. 故障注入：摄像头/麦克风断开、窗口关闭、显示器变化、锁屏/睡眠、GPU 丢失、磁盘不足、进程终止、工程 JSON 损坏。
5. 验证异步旧回调、关闭期间保存、导出取消、重复启动和快速项目切换；使用 session/revision 诊断证明无串写。
6. 依据实际瓶颈调整队列/缓存/代理分辨率，设置可解释的降级提示；不牺牲源媒体或最终导出质量来掩盖预览问题。
7. 补齐键盘焦点、可访问名称、高对比度、中文/英文、快捷键冲突，以及日志脱敏。
