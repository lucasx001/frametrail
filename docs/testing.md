# 测试与验收入口

更新：2026-10-25。测试结果必须说明它验证了哪一层；一种测试不能自动代表另一层已经通过。

| 层级 | 入口 / 证据 | 能说明什么 | 不能据此确认什么 |
|---|---|---|---|
| CPU 与契约 | `scripts/test.cmd`、CTest、托管 TRX | 时间线映射、领域验证、控制器状态、缓存和保存契约 | 真实 WinUI 焦点、鼠标命中、帧呈现 |
| 应用方法集成 | `scripts/validate-workflows.cmd`；`workflow-validation.json` | 实际 WinUI 窗口、原生录制/预览/导出、保存和资源释放链 | 操作系统实际鼠标/键盘输入是否触达对应控件 |
| 独立媒体检查 | 工作流脚本中的 ffprobe / ffmpeg | 输出轨道、尺寸、时长和全片独立解码 | 听感、跨 GPU 像素一致、长时同步 |
| 实际输入 | Computer Use 或人工操作记录、系统窗口截图与结果工程 | 点击、拖动、键盘、焦点与可见结果 | 其他 DPI/设备、长期资源趋势、安装矩阵 |
| 扩展矩阵 | 0010 / 0011 / 0012 及相应 validation 文档 | 明确记录的硬件、DPI、长时、发行环境 | 未在矩阵中执行的环境 |

`tests/FrameTrail.App.Tests` 是 net8.0 辅助逻辑测试，部分源文件通过 Compile Link 纳入测试程序集。它不加载产品 WinUI 窗口。应用内部 self-test 可以调用生产手势或按钮处理路径，但报告中必须称作“应用方法自测”，不能称作真实拖动或真实键盘验收。

## 三条可重复工作流

先构建原生和应用，再在已登录的 Windows 桌面运行：

```powershell
.\scripts\build.cmd -Configuration Release -NativeBuildDirectory "$PWD\artifacts\native-release" -LockedRestore
.\scripts\validate-workflows.cmd -NativeBuildDirectory "$PWD\artifacts\native-release"
```

`-OutputDirectory` 可指定新的证据目录；已有目录会被拒绝，旧结果不会覆盖。`-ToolchainRoot` 支持独立 worktree 共用已安装工具链。脚本默认重新构建 WinUI 应用，`-SkipBuild` 仅用于明确刚构建过的同一代码。脚本不会修改全局 PATH、安装软件、接入用户工程或删除用户素材。

1. **录制 → 停止 → 编辑 → 导出**：应用自己创建一个动画 WinUI 窗口，通过真实 WGC 窗口采集，暂停/继续后停止。仅在新测试工程内添加合成静音 WAV，重新打开编辑器、分割并自动保存，导出 640×360 MP4；脚本独立检查视频/音频轨并全片解码。不会录制桌面、麦克风或系统声音。
2. **效果手势 → 一次撤销 → 保存重开**：在真实编辑窗口添加遮挡，使用投影几何调用生产 CanvasOverlay 手势方法；确认移动结果，一次撤销恢复全部创作内容，关闭、释放工作区后重新从磁盘打开，并比较工程内容和重新渲染。它验证手势处理链，不声称注入了 OS 鼠标输入。
3. **播放与后台任务 → 切换／关闭工程**：用可取消的准备屏障确定性保持真实音频峰值任务等待，同时启动静音轨的原生播放。经生产切换路径打开另一测试工程，确认旧窗口关闭、旧工程租约可重新获得；对新工程重复播放与后台准备，再关闭、释放并重新获得租约。超时或无法关闭将失败，不能记成通过。

根目录 `workflow-summary.json` 汇总三链和独立解码结果；`application/workflow-validation.json` 记录每条链、捕获范围和失败原因。PNG 来自 WinUI / 原生预览，不冒充系统屏幕截图。所有自测报告固定 `actualInputVerified=false`，并保留实际输入待验收说明。

## 对应的真实输入走查

在同一修订、同一构建上另外执行并记录：

1. 通过录制胶囊选择测试窗口、开始/停止、打开编辑、点击导出；核对成片与轨道。
2. 用实际鼠标拖动效果、Ctrl+Z、关闭并重开；确认位置、焦点、一次撤销和保存结果。
3. 实际点击播放并切换项目、关闭编辑器；确认无声音残留、预览残留、未保存丢失或锁定工程。

记录应用路径、Git 修订、系统/DPI、输入方式、观察结果、截图/工程/输出路径及未执行项。可先运行统一应用方法自测，再执行实际输入；两份结果分别保留，不把其中一份的标志改为另一层。

## CI 与交付边界

普通 CI 继续执行确定性的原生与托管单测；工作流窗口自测需要可用的登录桌面、WGC 与图形设备，不能在没有桌面的 runner 上以“跳过”冒充通过。实际输入、真实外设、长时联合音画同步和安装升级依旧按各自验收任务执行。
