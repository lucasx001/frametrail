# 0003 主 agent 采集验收记录

日期：2026-10-14。测试材料在本地 `artifacts/validation/`，不提交录屏或窗口标题列表。

2026-10-15 补充：下方 CPU 回读及 44.14 FPS 为旧实现的历史结果。GPU 编码输入与受控短测见 [连续性与性能记录](capture-continuity-performance.md)，新路径长测仍待执行。

## 环境

- Windows 11 x64 build 26300（本机是预览系统，不能替代稳定版系统矩阵）。
- NVIDIA GeForce RTX 4060 Laptop GPU，驱动 32.0.16.1692；另有 AMD Radeon 610M，驱动 32.0.21025.1024。
- 当前显示器 2560×1440，系统报告 DPI 115，SDR。
- WGC 可用；枚举到 3 个硬件 H.264 编码器、1 个软件编码器。

## 已执行

1. subagent 进行真实区域短录制和暂停/恢复；记录 3 秒录制加约 2 秒暂停，81 帧、暂停 2.003 秒、无队列丢帧。此短测的文件与详细日志在 `artifacts/capture-local/`。
2. 主 agent 尝试对动态测试窗口长录制；SDL 窗口尺寸变化后，采集返回 0x8007139f 并安全结束，保留约 23 秒视频。这验证了明确的尺寸变化终止路径，不算长录制通过。
3. 改为固定显示器内 1920×1080 区域，设置最大 60 FPS，连续请求录制 600 秒。生成 H.264 MP4 604.425250 秒、26,680 帧、346,705,658 字节，最终 HRESULT 0、Stopped；实际墙钟包含测试循环开销。日志为 `capture-region-600s.log`。
4. `ffprobe` 核验编码、尺寸、时长、帧数；`ffmpeg -v error -i ... -f null -` 完整解码返回 0，错误日志为空。
5. 两次资源采样：工作集约 119.8MB→120.6MB，私有内存约 203.5MB→208.2MB，句柄 951→941；仅是两点观察，不证明长期无泄漏。
6. 最终静态 CRT 构建进行整屏短录制：2560×1440、H.264、22 帧、3.0159 秒，hardware active=1、最终 HRESULT 0。静态桌面没有每秒 30 个不同画面，实际帧数不作为该场景失败条件。

## 结果与限制

- 队列丢帧 2，限速丢弃 8，队列高水位 3，确认硬件编码 active=1。
- 实际平均约 44.14 FPS，并未达到 60 FPS；采集、后台构建和桌面同时运行，尚未完成独占基线或瓶颈分析。记录的是实际不同样本，不通过补帧伪装 60 FPS。
- `ffprobe r_frame_rate=120/1` 是对可变时间戳流的推断；不代表已录到 120 FPS，产品限额仍为 30/60。
- 当前原型为 GPU 裁切/色彩转换后 CPU readback 到 MF writer，尚非全 GPU 编码提交链路；性能优化留在后续任务。
- 还没有完成 125%/150%/200% 与负坐标多屏实机验收、拔插显示器、稳定版 Windows、HDR 切换及编码器故障注入；不得勾选为通过。
- 这段长测没有音轨，不构成 30 分钟音画同步验收。

## 主 agent review 修正

- 指出以“距上一帧至少一个帧间隔”限速会因微小抖动产生隔帧；subagent 改为会话时间 bucket，不累计该节奏误差。
- 统一增加原始 QPC 的 pause_at/resume_at，供多轨共享暂停边界。
- 原生模块改用静态 CRT，避免开发机器缺少 Debug CRT 或加载不匹配的宿主 C++ 运行库；最终集成构建另记。
