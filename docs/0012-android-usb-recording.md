# 0012 — Android 手机 USB 录屏

状态：待验收。阶段：M5，首版后扩展。依赖：0002–0008、0010–0011。规格依据：[spec.md](spec.md) 3.5–3.6。进度入口：[progress.md](progress.md)。需求日期：2026-10-15。

## Task 整体描述

将移动设备录屏方向改为：用户通过支持数据传输的 USB 数据线连接 Android 手机，在 FrameTrail 内选择设备、检查画面与声音、开始录制，并将素材保存为可重开、剪辑和导出的工程。Windows 端继续采用 WinUI 3 与 C++ 原生架构。

本任务不承担 iPhone/iPad 有线采集。按 2026-10-16 用户要求，从 main 切换到 `codex/m5-android-usb` 提前实现 M5；M4 的硬件/分发前置验收继续保留，不因本次实现提前判定通过。当前代码与自动验证已完成；用户暂时没有手机，本次不进行 USB 真机验收。

## Task 具体实现逻辑

### 1. USB 发现与连接引导

- ADB 仅用于已连接手机的枚举、授权状态、设备服务启动与 USB 隧道。区分无设备、`unauthorized`、`offline`、可用和版本不兼容；排除模拟器与 TCP/IP 连接，多台手机时明确选择目标 USB transport。
- 引导用户开启开发者选项、USB 调试并在手机端确认本机 RSA 授权。只有充电功能的线缆、驱动缺失和授权未完成时，提供具体排查步骤。
- 驱动安装由用户按官方指引处理；应用不自动安装驱动、提升权限或更改手机调试设置。支持范围只包含具备可用 ADB USB 链路的设备，不承诺所有品牌和 ROM。
- 使用参数列表启动工具，不拼接 shell 命令；子进程与隧道绑定 RunId，超时、取消、关闭后释放。只清理本会话资源，不通过全局 `adb kill-server` 中断 Android Studio 等其他程序。

### 2. 原生媒体接入

- 固定 ADB、scrcpy server、协议解析器的配套版本、官方来源和文件校验。scrcpy 的内部协议可能随版本变化，升级时重新验证，不假定兼容；通过 `scripts/setup-android.cmd` 下载并验证固定运行时，构建/发布复制到应用目录，不依赖开发机 PATH。
- Android 端复用 scrcpy 原生采集服务，经 ADB USB 隧道发送视频、可用音频、编码配置与媒体 PTS。Windows 端实现 `AndroidCapture` C++ 来源适配器，通过现有 C ABI 汇报状态、错误和能力。
- H.264 为默认视频协商格式，探测尺寸、码率及帧率上限。Media Foundation 负责 Windows 侧解码、封装和必要的编码；预览通过 D3D11 进入现有渲染链路，像素不经过 C# 数组。
- 本轮实现直接保存兼容 H.264 样本的路径，协商无 B 帧及一秒关键帧间隔，每个恢复分段从可独立解码的关键帧开始。不满足单调时间戳、配置或容器约束的设备会明确失败并保留检查点，不静默生成坏文件；自动重编码兼容路径不在本轮已验证范围。
- 调用官方 scrcpy 可作为设备验证工具；正式功能直接接收媒体流，不依赖外部投屏窗口的位置、遮挡或窗口捕获。
- 第一阶段只录制一台手机主画面。录制开始后固定方向和输出尺寸；旋转导致尺寸变化时安全结束并提示重新开始。手机远程控制、剪贴板同步、无线连接和动态旋转连续录制不在本任务范围。

### 3. 声音与时钟

- 视频按 Android 5.0 / API 21 起评估，手机内部音频按 Android 11+ 探测；Android 11 开始采集时需要解锁。具体可用性依赖系统、ROM 和应用，必须在 UI 显示能力结果。
- 手机内部音频、Windows 系统声音和 Windows 麦克风为不同来源。音频不可用时允许无声视频或电脑麦克风旁白；不生成虚假的有效手机音轨，也不以 WASAPI loopback 替代手机内部音频。
- 手机音频不支持或启动失败时，按用户选择继续无声录制或取消；只有主视频首帧与必选音轨准备好后才进入 Recording。
- 以首个有效手机视频帧对应的设备媒体时间作为原点，保留设备音视频 PTS 的相对关系，并估计其到 Windows QPC 的偏移与漂移。USB 包到达时间包含抖动，不能直接用作录制时间。
- 与电脑麦克风并录时，单独验证跨设备漂移与必要的受控重采样；不得把 USB 传输延迟当作设备 PTS。暂停时媒体链路可继续排空，丢弃暂停区间，再用共同暂停偏移重建成片时间。
- 默认不播放手机预览声音，避免又被电脑系统音捕获；如果用户启用监听并同时选择 loopback，应明确提示重复收音。

### 4. 工程、编辑与异常处理

- 提炼主来源适配接口，让桌面与 Android 来源复用 RecordingCoordinator 的开始、暂停、标记、分段、停止和恢复流程，保持现有桌面路径回归通过。
- 为主来源类型、手机独立音轨与必要的方向/尺寸信息设计下一版 schema；补 C# DTO、C++ 严格校验、旧工程迁移和往返测试。桌面 schema 1 严格读写保持不变；Android 使用 schema 2 的 `primarySource` 与 `androidAudio`，不把手机音轨冒充 `systemAudio`。
- 原始主视频、独立声音和可重建缓存都按现有规则存入工程。断开手机后仍能重开、剪辑、混音、套用通用画面效果与导出。
- Android 屏幕没有 Windows 光标事件。标记继续可用；Windows 鼠标不得作为手机触摸记录，缺少真实触摸输入时不生成基于点击的自动运镜。
- 拔线、授权撤销、服务崩溃或主媒体超时时结束录制，尽量 finalize 当前分段，保留已完成分段和最近有效工程。最后未完成 MP4 仍按现有恢复策略排除，不承诺修复。
- 重新连接后回到设备检查流程，由用户新建录制；旧 RunId 的回调与残留包不能写入新工程。普通日志只保存脱敏设备标识，不记录完整序列号或屏幕内容。

### 5. 分发与验收

- 单独核验 ADB、scrcpy server 及实际引入的编解码/运行时组件的来源、许可证、版本和可分发条件；保留适用的 LICENSE/NOTICE，不把 scrcpy 的许可证等同于整个工具包的许可。
- 在无 Android Studio、无开发机 PATH 的干净 Windows 机器验证安装后的设备发现与启动；驱动缺失时给出指引，避免依赖开发机已有 ADB 环境。
- 增加不同 Android 版本、品牌、USB 控制器/线缆、授权与锁屏状态的矩阵。复用 0010 的资源、恢复与音画测量方法，Android 结论单独记录；重新验证新增组件的安装、更新和卸载。
