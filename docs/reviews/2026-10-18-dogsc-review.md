## 结论与范围

FrameTrail 已具备录制 → 工程 → 编辑 → 预览 → 导出的主要闭环，Windows 原生分层和非破坏性编辑方向清楚。当前主要差距是画布直接操作、录前反馈等交互完整度，以及长工程性能和硬件/发行验收。不能把已有功能重新列为未实现，也不能把本机自动测试通过视为达到 DogSC 的全部体验。

本轮读取两边本地源码、FrameTrail 规格/任务/验证文档，并执行默认测试。未在 Mac 上运行 DogSC，未进行本轮逐像素 UI 对照、真实录制、USB 手机测试或线上 Release/Store 状态查询。下列“未验收”表示仓库尚缺闭环证据，不等于功能失败或外部动作一定尚未发生。

测试命令：`scripts/test.cmd -Configuration Release -NativeBuildDirectory <workspace>/artifacts/native-release -LockedRestore`。7 组原生测试通过；托管 30 + 6 + 111 + 62 = 209 项通过，Audio 测试项目没有匹配默认过滤器的用例。原生使用已有 Release 产物，本轮未全量重编译应用/引擎，也未启用 `IncludeHardware`。

## 对照发现与实施 TODO

### P1 基线：画布直接操作（现已实现，见 0022）

DogSC 的 `EditorCanvasOverlayInteraction.swift` 有遮挡区域和贴图的选中、拖动、角点调整与悬停反馈，`EditorLinearFocusCanvasOverlay.swift` 有聚焦区画布交互。FrameTrail 的 `EditorWindow.xaml` 中预览主体是挂载媒体画面的 Grid，当前裁切入口在 `EditorWindow.Chrome.cs:105` 仅跳转检查器，裁切位置/大小通过数值框设置。未发现对应的完整画布对象编辑层。

- TODO：补充裁切框、贴图/遮挡/聚焦选中框、移动/缩放手柄及坐标换算。
- 验收：普通/全屏/不同预览倍率/DPI 下命中与渲染一致；拖动只产生一次撤销，Esc 取消，保存重开和导出结果一致。
- 这是交互能力差距，不是底层裁切/遮挡/贴图未实现。

### P1 基线：声音准备与 RIFF 上限（现已实现流式预览/RF64，见 0024）

`EditorWindow.Assets.cs` 对完整输出时间线建立 `mix.wav`；`EditorWindow.xaml.cs:254` 的播放入口在有音轨但缓存未完成时直接返回。原生 `media/audio.cpp:87` 起生成 48kHz、双声道、16-bit PCM，并拒绝超过 RIFF 4 GiB 的输出。

- 30 分钟混音约 330 MiB；输出超过约 6.2 小时触发上限，慢放会更早碰到源时长对应的限制。
- 音频不是一次性全部装进内存；问题在于完整磁盘缓存、准备延迟和文件格式上限。
- `media/export.cpp:105` 导出再次混音，当前没有直接复用预览混音的路径。
- TODO：分块/渐进准备，提供就绪进度和显式静音预览；考虑流式导出或 RF64，增加缓存容量设置/清理入口。
- 验收：30/60/120 分钟工程首个可播放时间、磁盘峰值、反复变速/撤销后的缓存复用与取消行为。

### P1 基线：录前摄像头反馈（现已实现，见 0023）

DogSC 有独立 `CameraPreviewWindow.swift`，可呈现录制摄像头画面。FrameTrail 的 `MainWindow.xaml.cs:265` 当前主要枚举摄像头格式，录制面板提供设备/格式选择；未发现对应的桌面摄像头录前实时预览窗口。不要与已有编辑器摄像头轨渲染或 Android 实时预览混淆。

- TODO：复用采集源提供摄像头实时预览及镜像显示选项，明确显示镜像与导出镜像的关系。
- 验收：独占摄像头、录制切换不二次抢占、设备拔插、29.97 FPS 与同步。

### P2：时间线浏览和属性复用仍有差距

DogSC 的 `EditorPlaybackHoverPreview.swift` 支持独立悬停预览及离开后恢复播放状态；FrameTrail `EditorTimeline.cs:178` 在未按鼠标左键时直接返回，现有路径是点击/拖动 seek。

DogSC 的 `EditorEffectTransfer.swift:94` 支持仅粘贴属性。FrameTrail `EditorWindow.xaml.cs:401` 的复制/粘贴是运镜检查器内的效果副本；没有单独的属性粘贴命令。

- TODO：悬停预览、取消悬停恢复、异步 seek 合并/过期拒绝；仅粘贴兼容属性且保留目标时间和身份。
- 补齐完整快捷键说明；不能把已有复制效果误写成完全没有复制能力。

### P2：导出逐帧 GPU 回读值得专项优化

`media/export.cpp:45–54` 在 GPU 转 NV12 后通过 staging texture、`CopyResource`/`Map` 回读，再创建 CPU buffer 交给编码器。硬件编码开关不等于端到端零拷贝。

- TODO：评估 D3D texture → MF surface 编码路径，保留显式兼容回退；复用帧缓冲，减少每帧分配。
- 验收：相同素材/效果下 1080p/4K、30/60 FPS 的导出耗时、CPU/GPU、内存、取消响应及成片一致性。
- 属于代码确认的拷贝成本；本轮没有测得它在所有机器上构成主要瓶颈。

### P2：长时间线与大量项目需要性能验收

时间线已经按可见区绘制，播放头移动也只改位置；不是每个播放帧重建整条时间线。但 `EditorTimeline.Draw()` 会清空重建可见 XAML，滚动与每张缩略图返回都会调用；大量效果仍有线性扫描。

项目列表在后台读取目录，但 `ProjectLibraryWindow.RenderRows()` 为所有过滤结果创建控件并放入 ListView；ListView 不会消除预先创建全部控件的成本。

- TODO：缩略图回调批量刷新、复用可见控件/绘制层、效果区间索引；项目列表采用数据项/模板、搜索节流，按压力测试结果决定分页。
- 验收：多小时/数千片段工程、密集效果、100/1000 个项目、高速滚动/缩放时的 UI 延迟、内存和句柄。
- 默认 4K 是现有产品选择，应保留；可增加耗时统计或可选性能策略，不能因尚未压测便判定该默认值错误。

### P2：更新入口与分发方式不匹配

DogSC 的 `AppUpdateController.swift` 接通 Sparkle 正式版更新。FrameTrail `EditorSettingsWindow.cs` 的“检查更新”使用 `Package.Current.CheckUpdateAvailabilityAsync()`；EXE/便携版没有该包身份时只显示回退说明，没有 GitHub 版本查询/下载引导。

- TODO：按 Store/MSIX 与 EXE/ZIP 区分更新来源；至少为站外版本提供真实版本检查、版本说明及官方下载入口。
- 更新安装器如后续引入自动化，应复用任务/保存屏障，避免中断录制、导出和未保存工程。
- 不应照搬 macOS 的 Sparkle 实现。

### P2/P3：设置、本地化与易用性

DogSC 有 `AppLocalization.swift` 和权限/首次启动相关流程；FrameTrail 目前大量中文字符串直接写在 XAML/C#，设置里的权限页主要为说明文字。

- P2：建立资源化文案与中英文切换；首次使用的来源/声音/权限说明；从设备错误跳转系统设置的可操作引导。
- P2：完整键盘工作流、焦点和读屏验收。时间线的片段视觉由 Canvas 内不可命中的元素绘制，应补可访问选择与操作语义。
- P3：自定义光标素材/更多样式、独立预设包导入导出、缩略图式预设管理。
- 工程优化：应用项目编译包含多组验证 partial 类，后续可将验证入口集中到独立 harness 或受构建配置控制，降低维护耦合；不把这一点当作已证实的发布漏洞。

## 建议推进顺序

1. 先做桌面长时联合录制与磁盘/外设故障验收，确认数据可靠性，并登记真正失败的可复现缺陷。
2. 优先补画布直接编辑、录前摄像头预览和声音渐进准备，改善高频使用体验。
3. 再做悬停预览、仅粘贴属性、更新入口、可访问性/快捷键与本地化。
4. 用性能测量决定导出零拷贝、时间线/项目列表优化的投入；并行程式化准备发行验收，但真机和商店认证仍需独立完成。
